# GitBand

> 让每个仓库，用对账号。

GitBand 是一款本地 Git 账号管理工具，适合在同一台电脑上切换个人、工作和不同托管平台的身份。集中管理 SSH / HTTPS 凭据，为项目绑定账号，再继续使用你熟悉的终端或 IDE 开发。

**Windows x64 · SSH / HTTPS · 简体中文 / English · Apache-2.0**

[下载](https://github.com/thaintus/GitBand/releases) · [快速上手](#快速上手) · [使用指南](aBase/doc/USER_GUIDE.md) · [反馈问题](https://github.com/thaintus/GitBand/issues)

## 主要功能

| 功能 | 说明 |
| --- | --- |
| 多账号管理 | 保存提交姓名、邮箱、HTTPS 凭据和 SSH 私钥，设置默认账号 |
| 项目绑定 | 为每个仓库选择账号，查看登记的绑定与生效账号，手动同步外部修改 |
| 项目整理 | 添加本地目录、搜索项目、管理分组；长按拖动账号、平台、项目和自建分组排序 |
| 全局模式 | 临时使用统一账号，关闭后恢复原全局配置及各项目绑定 |
| 仓库操作 | 按账号克隆、测试连接、快进拉取，支持按分组批量拉取 |
| 地址与平台 | 修改远程地址、转换常规 SSH / HTTPS 地址，管理自建 Git 平台 |
| 日常使用 | 中英文切换、托盘驻留、打开项目目录、重新定位已移动的项目 |

提交、推送、分支管理和冲突处理仍由终端或 IDE 完成。应用通过系统 Git 工作，无需替换 Git。

## 下载与安装

前往 [Releases](https://github.com/thaintus/GitBand/releases)，按操作系统选择附件。**可下载版本和平台以发布页实际附件为准**；若没有适用的附件，可参考[开发与构建指南](aBase/doc/DEVELOPMENT.md)。

| 平台 | 下载与使用 |
| --- | --- |
| **Windows x64** | 主要发行平台，选择 `GitBinder-<版本号>-setup.exe`，按安装向导操作 |
| macOS | 实验包，支持 Apple Silicon / Intel；未完成签名、公证及实机验收，先阅读 [macOS 说明](aBase/doc/MACOS_PACKAGING.md) |
| Linux | 实验包，提供 x64 / ARM64 的 `.deb` 和 `.tar.gz`；依赖与桌面要求见 [Linux 说明](aBase/doc/LINUX_PACKAGING.md) |

Windows 安装前：

- 安装系统 Git；使用 SSH 仓库还需可用的 OpenSSH。
- 安装包已包含 .NET 运行时，无需另外安装 .NET SDK 或 Runtime。
- 安装向导需要管理员权限。当前安装包未配置代码签名，请核对下载来源；发布页提供 SHA-256 时可比对文件哈希。

升级时先从托盘菜单退出旧版本，再运行安装包。程序与用户数据分开存放。

> 仓库与窗口标题使用 GitBand；部分界面文字仍显示 GitBind，安装包、程序文件和数据目录沿用 GitBinder 名称。

## 快速上手

1. **检查环境**：打开“设置”，确认 Git / SSH 路径，必要时点击“重新检测”。
2. **添加账号**：在“账号”填写提交姓名、邮箱及所属平台，再按仓库协议填写 HTTPS 凭据或导入 SSH 私钥。邮箱可留空，具体影响见[提交身份说明](aBase/doc/USER_GUIDE.md#提交姓名与邮箱)。
3. **添加项目**：在“项目”选择已有目录，或点击“克隆仓库”下载到新目录。添加已有 Git 仓库时会尝试绑定已启用的默认账号；克隆使用弹窗中选择的绑定账号。
4. **绑定账号**：在项目卡片的“绑定账号”下拉框中选择账号，选择后立即应用。普通目录首次绑定会先询问是否初始化 Git。
5. **测试连接**：配置远程地址后，点击账号旁的测试图标。成功后可继续在终端或 IDE 中使用仓库。

> **提交署名与远程权限是两回事。** 姓名和邮箱决定提交记录中的身份，SSH Key / HTTPS 凭据决定远程访问权限。“测试”仅验证能否读取远程引用，不代表拥有推送权限。

## 常用操作

### 在其他工具里改了 Git 配置

点击**项目名后的刷新图标**。应用读取该项目当前的远程地址、Git 姓名和邮箱；能够唯一匹配已启用账号时，直接更新软件内的绑定记录，无法匹配或存在歧义时弹窗提示并保留原记录。

刷新不联网、不写入 Git 配置，也不验证远程认证。启动只恢复登记信息，不重新应用绑定；进入项目页仍会读取本地远程地址等元数据。完整规则见[刷新与外部修改](aBase/doc/USER_GUIDE.md#刷新与外部修改)。

### 调整显示顺序

在账号、平台、项目卡片或自建分组的**名称或空白处长按约半秒**，随后拖动。列表实时让位，松开保存当前预览顺序，按 `Esc` 取消。搜索或分组筛选下排序只调整可见条目的顺序。

### 临时统一使用一个账号

在顶部选择账号并开启全局模式。应用内生效顺序为：

```text
全局模式账号 > 项目绑定账号 > 默认账号
```

开启时会写入当前系统用户的 Git 全局配置，并覆盖已绑定仓库的相关配置；关闭后恢复。**退出应用不会关闭全局模式。** 未登记仓库仍遵循 Git 自身的配置优先级，已有本地配置可能覆盖全局配置。详见[账号生效规则](aBase/doc/USER_GUIDE.md#账号生效规则)。

## 常见问题

**添加或移除项目会修改本地文件吗？**

仅添加普通目录不会初始化 Git；首次绑定或保存远程地址时会先询问。移除项目会先解绑并恢复保存的配置，再移除登记记录，不删除本地源码。删除分组也不会删除项目。

**IDE 可以拉取，为什么这里测试失败？**

请检查仓库地址协议与账号凭据是否匹配。GitBand 使用已录入账号的认证信息，不能直接借用 IDE 内部保存的密码或会话。SSH 未知主机、带口令私钥等情况见[连接问题排查](aBase/doc/USER_GUIDE.md#连接问题排查)。

**关闭窗口后为什么还在运行？**

Windows / macOS 默认隐藏到托盘，可在托盘菜单退出，或在设置中关闭驻留。Linux 默认关闭窗口即退出，确认桌面支持托盘后可手动开启。

**升级、卸载或换电脑时要注意什么？**

卸载前先关闭全局模式并解绑相关项目，避免 Git 配置继续指向已移除的凭据助手。数据目录与系统凭据存储不能直接作为跨设备迁移包，详见[数据与迁移](aBase/doc/USER_GUIDE.md#数据与迁移)。

## 数据与凭据

本地管理无需注册云端账号；测试连接、克隆和拉取需要网络。Windows 数据默认位于 `%LOCALAPPDATA%\GitBinder\`，也可在“设置”查看实际路径。

HTTPS 凭据由系统机密存储保护：Windows 使用当前用户 DPAPI，macOS 使用登录钥匙串，Linux 使用 Secret Service。**导入的 SSH 私钥保存为文件副本**，需要妥善保护数据目录。

> [!WARNING]
> 平台分类不限制凭据可用于哪些主机。当前 HTTPS 凭据助手不会按账号所属平台的 Host 限制凭据返回；绑定账号、修改地址和开启全局模式前，请确认远程地址可信。
