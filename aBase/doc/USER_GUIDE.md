# GitBand 使用指南

[返回项目首页](../../README.md) · [开发与构建](DEVELOPMENT.md)

本指南介绍日常操作及其对本地 Git 配置的影响。下载和首次配置请从[快速上手](../../README.md#快速上手)开始。

## 账号生效规则

应用内选择账号的优先级为：

```text
全局模式账号 > 项目绑定账号 > 默认账号
```

### 绑定、默认账号与解绑

- 在项目卡片中选择“绑定账号”即保存并应用，无需额外点击保存。全局模式开启时，项目保留所选绑定，实际使用全局账号。
- 新登记的 Git 仓库会尝试自动绑定已启用的默认账号；普通目录不会。普通目录后来初始化为 Git 仓库时，也不会仅因重新进入项目页而自动绑定。
- 默认账号是应用内的默认选择，不会在普通模式下接管所有未登记仓库。
- 首次应用绑定前保存相关 Git 配置快照；解绑时恢复该快照。移除项目先解绑，再删除登记记录，不删除本地源码。
- 账号编辑保存可能同步已绑定仓库的配置。若提示“账号已保存，但配置同步失败”，请处理错误后重新保存，确认成功再继续提交。
- Git 操作进行中会限制可能冲突的改绑、账号编辑、删除及全局模式切换。若恢复配置失败，或无法确认 Git / SSH 已退出，请按错误提示核对状态后再重试。

“绑定账号”是软件登记的关系，“生效账号”是按上述规则计算的结果。它们不是远程服务器认证结果，也不代表其他工具没有覆盖 Git 配置。

### 全局模式

开启全局模式会保存当前系统用户的相关 Git 全局配置，再写入所选账号的提交身份与认证配置，并同步覆盖已绑定仓库。涉及姓名、邮箱、SSH 命令和凭据助手等配置，**不把密码或 Token 写入 Git 配置**。

关闭后恢复原全局配置，并重新应用各项目的绑定账号。开启期间不会将项目绑定关系改成全局账号。关闭窗口或退出应用不会关闭全局模式，也不会撤销已经写入的配置。

未登记仓库仍遵循 Git 自身的配置优先级，本地配置、环境变量及命令行参数可能覆盖全局设置；IDE 自己的凭据管理也可能改变认证行为。

### 提交姓名与邮箱

账号的提交姓名和邮箱决定提交署名，与平台登录凭据分开维护。

**邮箱留空表示新提交不携带邮箱地址，不是继承全局邮箱。** 应用账号时会明确设置空的 `user.email`、`author.email` 和 `committer.email`；填写邮箱时，三项同步使用该邮箱。部分平台或仓库策略可能拒绝空邮箱，请按目标平台要求设置。

该设置不删除历史提交中的邮箱，也不改写变基、挑拣或修改提交时保留的原作者信息。终端或 IDE 的显式参数仍可能覆盖它，不能将其视为对所有工具的强制隐私拦截。解绑或关闭全局模式会恢复保存的配置。

启动应用只恢复已登记信息，不重新应用已有绑定。修改账号后需要同步配置时，应执行明确的保存操作。

## 项目与目录

### 添加目录或配置远程地址

已有仓库使用“添加项目”登记；尚未初始化 Git 的普通目录也可以添加、分组和整理。

普通目录首次绑定账号或保存有效远程地址时，会先询问是否在该目录初始化 Git。确认后保留现有文件，不自动下载、提交或上传，也不接管父级仓库。仅添加目录、启动或进入项目页不会初始化 Git。

没有 `origin` 的 Git 仓库也可以绑定提交身份。测试连接需要配置 `origin`；拉取使用当前分支跟踪的远程，没有跟踪关系时才尝试 `origin`。

“修改地址”维护的是仓库的 `origin`。输入框中的协议切换只修改草稿，保存后才写入仓库；再次点击修改按钮或取消会丢弃草稿。常规地址示例：

```text
SSH    git@github.com:your-org/your-repo.git
HTTPS  https://github.com/your-org/your-repo.git
```

自定义端口等非标准地址请手动填写。修改地址不会搬迁远程代码或自动更换绑定账号；迁移平台后请确认目标仓库、地址和账号，再测试连接。

### 刷新与外部修改

| 操作 | 行为 |
| --- | --- |
| 启动应用 | 恢复保存的账号、项目、分组及全局模式展示，不重新应用 Git 配置 |
| 进入项目页 | 先显示登记信息，再从本地读取仓库状态及远程地址等元数据；不联网、不重写身份配置 |
| 点击项目名后的刷新图标 | 读取当前项目远程地址、Git 姓名和邮箱，尝试同步软件内的绑定记录 |
| 点击测试图标 | 使用当前生效账号访问远程，检查能否读取引用 |

手动刷新按姓名、邮箱及已知远程主机匹配已启用账号：

- **唯一匹配**：直接更新绑定记录和下拉框，不在卡片追加说明文字。
- **无匹配或多个候选**：弹窗提示，保留原绑定。当前姓名或邮箱为空时也不能自动匹配。
- **全局覆盖**：如果需要改绑却无法从全局身份反推项目原绑定，会提示并保留原记录。

刷新只读取 Git 配置并更新软件记录，不初始化目录、不向 Git 写回、不验证远程权限。无法匹配时，可核对账号信息或手动选择绑定账号；手动选择会应用该账号配置。

远程信息读取失败时保留上次保存的信息并显示原因。

### 项目目录移动了

在项目卡片底部点击“修改本地路径”，选择移动后的**同一项目**并保存。应用保留项目 ID、名称、分组、绑定和原配置快照，不移动文件，不改写 Git 配置。

已有 Git 仓库不能改到普通目录；不要将路径指向另一个仓库或新克隆副本。路径左侧的文件夹图标用于在系统文件管理器中打开目录。

## 搜索、分组与排序

账号、平台和项目页面支持即时搜索，只过滤已加载数据，不发起远程查询。项目搜索可与分组筛选叠加。

在分组侧栏点击加号新建、铅笔重命名；项目路径右侧的下拉框用于设置分组，选择后立即保存。“全部项目”固定显示；有未分组项目时显示“未分组”，项目下拉框始终保留该选项。删除分组只将项目移回未分组，不删除项目或解绑账号。

账号、平台、项目和自建分组支持长按排序：

1. 在名称或卡片空白处按住鼠标左键约半秒，再拖动。
2. 拖动项以浅色背景和细边框突出，其他条目实时让位，当前布局就是松开后的顺序。
3. 松开保存，按 `Esc`、失去窗口焦点或在列表外释放会取消并恢复顺序。

“全部项目”和“未分组”是固定入口。筛选下排序只调整可见条目的槽位，隐藏条目保持原位；拖动项目不会改变其分组或绑定账号。平台未自定义排序时默认启用项在前，手动排序后使用保存的顺序。

## 连接测试与认证

账号可以同时保存 SSH 和 HTTPS 认证信息，实际使用方式由远程地址协议决定。编辑账号时，**HTTPS 凭据留空会保留已有凭据**，这与提交邮箱留空的含义不同。

连接测试执行只读的 `git ls-remote`。成功表示能够读取远程引用，不代表拥有推送权限；公开仓库也可能允许匿名读取。

绑定或测试时，若当前协议与账号已有认证方式不匹配，会询问是否转换远程地址。确认后才修改地址及相关认证配置；取消会保留原地址与已保存的绑定，并停止本次测试。双协议账号继续使用原地址协议。全局模式按全局生效账号判断，不批量静默改写地址。

> [!WARNING]
> 平台分类不是权限隔离。应用允许跨平台绑定，当前按账号固定的 HTTPS 凭据助手不会按平台 Host 限制凭据返回。请只对可信的远程地址使用账号凭据，并留意本机 Git 的地址重写规则。

### 连接问题排查

先确认项目地址、协议、当前生效账号和凭据。IDE 能拉取不代表 GitBand 已录入相同凭据；应用不会借用 IDE 内部保存的密码或会话，也不会在失败时回退到其他账号。

- **HTTPS**：录入平台允许的用户名和密码 / Token，并确认仓库访问权限。不要把密码或 Token 拼入 URL。
- **SSH 未知主机**：先在可信终端核实主机指纹并完成信任；应用不自动接受未知主机或绕过校验。
- **SSH 带口令私钥**：提前在应用使用的 SSH 环境中通过 Agent 解锁同一密钥；传输过程不弹出口令对话框。
- **SSH 权限、格式或签名错误**：按具体错误检查私钥与 Agent，应用不会自动修改私钥权限或切换到其他密钥。
- **代理或连接设置**：传输保留系统 / 全局 Git 的代理、CA、证书后端及地址重写配置。SSH 保留主机名、端口、代理及 known_hosts 等连接设置，认证仍指定当前账号的私钥。

Windows 传输优先使用所选 Git 安装目录配套的 OpenSSH，找不到时才使用系统定位结果。不要仅凭 IDE 成功推断两者使用了相同 SSH 程序、Agent 或连接配置。

## 克隆与拉取

### 克隆仓库

在项目页点击“克隆仓库”，填写 HTTPS / SSH 地址、绑定账号、已有父目录和新文件夹名称。目标新目录必须尚不存在；此功能按地址克隆，不通过平台 API 枚举仓库。

全局模式开启时实际认证使用全局账号，所选账号保留为新项目的绑定。传输显示进度并支持取消；失败时保留输入和可复制的错误信息。

失败或取消可能留下部分文件，应用不会自动清理。若代码已克隆但登记或绑定失败，请按提示添加项目或重新绑定，避免重复克隆。

### 拉取项目或分组

项目卡片的拉取使用当前生效账号，按当前分支跟踪的远程执行**快进更新**，可以是非 `origin` 远程。

- 已有提交但未设置跟踪时，仅尝试 `origin` 的同名分支；尚无提交时，查询 `origin` 默认分支并拉入当前本地分支。成功后保存跟踪关系。
- 分支不存在、跟踪配置不完整、历史分叉、分离 HEAD 或正在合并 / 变基时停止，不猜测其他分支。
- 本地改动或未跟踪文件会由 Git 判断能否安全更新；可能覆盖文件时停止。不自动 stash、reset、变基或创建合并提交，也不递归更新子模块。
- 拉取不会为匹配认证方式自动改写远程地址；请补齐凭据或修改正确远程的地址。

分组的拉取按钮在确认后依次更新**该组全部项目，不受搜索筛选影响**。某个项目失败不会阻断其他项目；支持取消并显示逐项结果，结果文字可选中复制。

单个项目的操作、进度和取消独立处理，其他项目仍可操作。批量拉取、分组结构修改及全局模式切换保留必要的冲突保护。克隆与拉取单次最长等待 30 分钟。

## 窗口与托盘

Windows / macOS 默认关闭窗口后驻留托盘，可从托盘菜单选择退出，或在设置中关闭驻留。Linux 默认关闭即退出，确认桌面提供托盘入口后再开启。

`Esc` 优先关闭下拉菜单、取消弹窗或项目地址 / 路径编辑；空闲主页面按 `Esc` 等同关闭窗口。保存期间暂不关闭；克隆时按 `Esc` 会先请求取消，等待操作结束。

## 数据与迁移

| 系统 | 默认数据目录 | 凭据保护 |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\GitBinder\` | 当前用户 DPAPI |
| macOS | `~/Library/Application Support/GitBinder/` | 当前用户登录钥匙串 |
| Linux | `$XDG_DATA_HOME/GitBinder/`；未设置或非绝对路径时为 `~/.local/share/GitBinder/` | libsecret / Secret Service |

数据库保存账号、项目、绑定、设置和配置快照等元数据；密码 / Token 保存在系统机密存储中，数据库只记录引用。Windows 数据目录中的 `secrets/` 是加密文件；`keys/` 是导入的 SSH 私钥副本，**不会额外使用 DPAPI 加密**。

- 在“设置”查看实际数据库和数据路径。备份前先正常退出应用，并妥善保护备份中的元数据与私钥。
- DPAPI 依赖当前 Windows 用户上下文；macOS / Linux 凭据在系统钥匙串或密钥环中。直接复制数据目录不是完整、可靠的跨用户或跨设备凭据迁移方案，换环境时需重新配置凭据。
- macOS / Linux 导入私钥目录和文件权限分别为 `0700` / `0600`。密钥环不可用或锁定时操作失败，不回退明文存储；同一登录用户下的应用不因此形成强隔离。
- Linux 需要可用的桌面会话和已解锁的 Secret Service，使用普通用户启动；桌面端与凭据助手应保持相同用户及 XDG 环境。
- 卸载或移动程序目录前，先关闭全局模式、解绑相关项目，再退出应用，避免 Git 继续引用旧的凭据助手路径。卸载不代替这些恢复操作。
- 反馈问题只提供脱敏信息，不上传密码、Token、私钥、真实数据库或含机密的完整 Git 配置。

macOS 和 Linux 的安装、系统依赖及实验状态分别见 [macOS 说明](MACOS_PACKAGING.md)和 [Linux 说明](LINUX_PACKAGING.md)。
