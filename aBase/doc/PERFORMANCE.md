# 性能与资源使用

## 安装包

Windows 发布策略为非单文件自包含共享目录，Desktop 与 Credential Helper 的同名依赖仅在 SHA256 相同时合并。发布/合并/Inno 三处控制 PDB，保留完整 .NET、SkiaSharp、HarfBuzzSharp、SQLite 依赖。用户仍无需另外安装 .NET。发布清单用于量化有效载荷，具体布局及 1.2.11 基线见 [Windows 打包说明](WINDOWS_PACKAGING.md)。

PDB 原始大小和相同 DLL 字节数不能直接换算为压缩后的下载包减量；包体积与进程工作集也分别核验。

## 列表与导航

- 账号、平台、项目卡片均位于有限高度的列表视口中，使用 VirtualizingStackPanel，只实现可见范围及框架缓存区。账号/平台允许普通容器回收；项目继续禁用跨行容器复用，避免即时保存的账号/分组下拉框写错项目。
- 账号/平台刷新按 ID 复用行 VM，回填新实体引用，并仅对发生变化的显示字段发通知。展示快照能识别 Fake/服务原地修改实体的情况；平台中英文状态由父 VM 的单一语言事件同步。Items/FilteredItems 使用集合 Move/插入/移除更新，保留搜索、拖动和行实例。
- Main 构造只设置初始导航，不启动额外总览读取；InitializeAsync 完成启动只读加载。导航按页面共享尚未完成的读取任务，最多保留固定页面集合的任务引用。显式保存、删除等操作后的刷新仍直接执行新的 VM.LoadAsync，不复用操作前的旧快照。
- 启动不扫描或写入仓库 Git 配置；正常进入项目页继续读取元数据，手动刷新继续读取当前配置并按既有规则同步记录。此处保留功能语义，不用取消刷新替代优化。

## 拖动、路径探测与日志

- 长按 500ms 到期后立即结束等待计时器。普通拖动由实际鼠标移动、集合变化、宿主状态和滚动事件驱动；只有指针处于边缘且仍可滚动时启用 30ms 计时器，到达边界或离开边缘即停止。
- Dispatcher 预览回调合并；源卡片使用缓存和 ContainerFromItem，只搜索其已实现容器，不按固定频率遍历全部控件。隐藏、最小化、视图卸载或 ItemsSource 替换时取消，并解除本次会话的临时事件。预览、保存和取消还原语义不变。
- ExecutableDiscovery 对 PATH 中成功命中使用 5 秒短期缓存，PATH 改变、文件消失/不可执行或过期时重新查找，不缓存失败。Git 的用户设置仍每次优先读取，缓存不改变用户指定程序的优先级；没有后台刷新计时器。
- GetGitDirAsync 直接使用隔离上下文中的 `git rev-parse --absolute-git-dir`，省掉相对路径再查询根目录的第二个进程。正常项目页元数据刷新当前通常为校验仓库与读取 origin 两条命令，不按旧实现的五六条进程描述收益。
- Avalonia Trace 只在 Debug 入口启用；业务日志配置保留。此处不改变应用单例间的正常事件订阅，不额外扩大页面强引用缓存。

## 核验边界

资源优化阶段完成语法树、XAML XML、API/接口/引用、脚本解析及 diff 静态校验，并补充条目复用/通知及 GitDir 读取的测试源码。随后按用户明确要求完成 1.2.12 生产发布编译及安装包构建：包大小从 73.37 MiB 降至 35.54 MiB（减少约 51.56%），版本、架构、无 PDB、共享依赖及哈希已核对。该包体积结果不等于运行时资源下降幅度。

2026-10-31 按用户“测一下”的明确要求，已运行 90 项定向单元测试；1.2.13 当前程序集的隔离 UI 套件 232 项、资源模式 37 项均通过。资源模式加载真实 Avalonia 样式和窗口，使用内存 Fake，未调用真实组合根、用户数据库、Git/远程认证、托盘和系统键鼠，也未控制已安装应用。303 个账号、303 个平台、304 个项目的顶部及底部实际容器数分别为 6、6、4；三轮、九次切页保留原集合和全部已有行 VM。四类排序预览/取消及账号排序提交重载也已验证。

### 当前空闲观测及波动

资源模式在全部操作和截图结束后回到账号页，每种状态稳定等待 5 秒，再观察约 5 秒。只在区间前后读取进程 CPU 时间，工作集和私有字节的两次探测置于 CPU 计时区间之外；不强制 GC，不清理工作集。当前 1.2.13 结果如下，内存单位为 MiB，箭头为两个端点，不能作为连续峰值。

| 状态 | 墙钟秒 / CPU 增量秒 | 平均一核 CPU | 工作集（前 → 后） | 私有字节（前 → 后） |
| --- | --- | ---: | --- | --- |
| 正常可见 | 5.0015 / 5.109375 | 102.16% | 371.86 → 332.09 | 278.30 → 236.54 |
| 仅测试宿主关闭缓存项目进度条动画 | 5.0068 / 5.125 | 102.36% | 332.05 → 336.87 | 236.11 → 240.70 |
| 恢复动画原值后隐藏 | 5.0024 / 0 | 0.00% | 31.62 → 38.57 | 241.69 → 241.74 |

百分比以一个逻辑核完全占用为 100%，多线程累计可以超过 100%；0 表示该短区间 CPU 时间读数未增加，不代表零功耗。当前可见两段分别观察到 GC 次数 17/17/0 和 16/15/1（0/1/2 代），高占用没有因关闭缓存项目进度条动画而下降。该进度条未附着当前窗口、宽高为 0，实验后恢复原值；没有据此修改产品进度条。

此前两次采用同一低干扰采样方法的 1.2.12 运行，可见平均一核 CPU 分别为 49.99% 和 0%，隐藏均为 0%。第一轮约 250 ms 轮询内存的结果另行保留，但包含采样器自身开销，不能作为产品空闲结论。各轮为独立进程，窗口遮挡/前台及渲染环境没有受控记录；不能将跨轮差异直接归因为具体代码或认定已修复。后续采样和对照已将排查范围聚焦到 UIAutomation 交互路径，具体请求方和分配来源仍未确定。**运行时低 CPU、低内存或低功耗的优化目标尚无验收结论。**

以下原始报告保存在仓库根目录的 `artifacts/`，未纳入 Git；列出的路径仅供本地追溯。

完整记录见三轮资源观测说明（`artifacts/verification-1.2.12-20261031/resource/README.md`） 和 1.2.13 最终资源回归（`artifacts/verification-1.2.12-20261031/resource-final/README.md`）。这些内存包含测试宿主、Fake 数据、截图和渲染器，不等于真实 18 项目的生产进程；隐藏后的工作集下降也不代表托管堆释放。没有优化前版本的同条件 A/B，没有瓦数或电功率测量。隔离宿主检查不代替安装、真实仓库/远程认证、托盘或生产场景验收。

### UIAutomation 隔离对照

随后 线程采样（`artifacts/verification-1.2.12-20261031/resource-cpu-trace/README.md`） 观察到 `Avalonia.Win32.Automation` 的 COM 回调链：`ABI_Navigate → AutomationNode.Navigate → Dispatcher.InvokeAsync/Task.InternalWait`，以及 `GetPropertyValue`、`GetFragmentRoot`、`RootAutomationNode.GetHostRawElementProvider`；同时有 `GC.RunFinalizers → ComObject.Finalize/ComWrappers.Release`。正常可见 5 秒内，Navigate/GetPropertyValue/GetFragmentRoot 的采样栈打开次数为 546/373/346，隐藏账号视图后为 40/31/17，恢复视图后再次增多。它们不是精确调用次数；等待栈占位和采样报告百分比不能当作 OS CPU 时间。

为进一步区分因素，在同一最新 1.2.13 测试 bin 中进行以下独立进程对照，采样方法保持不在 CPU 区间内轮询内存：

| 测试条件 | 正常可见 CPU 增量 / 墙钟秒 | 平均一核 CPU | 正常可见 GC（0/1/2 代） | 关闭缓存项目动画后 CPU | 主窗隐藏 CPU |
| --- | --- | ---: | --- | ---: | ---: |
| 仅派生隔离测试窗抑制 UIA peer | 0.03125 / 5.0023 | 0.6247% | 0 / 0 / 0 | 6.56%（GC 0/0/0） | 0.00% |
| 恢复默认 UIA 后复查 | 4.21875 / 5.0009 | 84.36% | 10 / 10 / 0 | 101.51%（GC 18/18/0） | 0.00% |
| 独立直接合成模式对照 | 0 / 5.0091 | 0.00% | 0 / 0 / 0 | 0.00% | 0.00% |

`--suppress-test-uia` 只让派生的隔离测试窗口 `OnCreateAutomationPeer` 返回 null，默认 WinUI 合成模式保持不变；恢复默认后高 CPU/GC 再次出现。该变化结合 UIA 高频采样，支持高占用与此环境中的 UIA 遍历/COM 交互相关；仍未确认具体外部客户端，也没有证明生产程序主动发起 UIA 扫描。`--direct-composition` 是另一项独立测试条件，单轮低占用不足以认定 WinUI 为根因。

原始报告分别为 UIA 抑制（`artifacts/verification-1.2.12-20261031/resource-uia-suppressed/resource-profile.json`）、恢复默认复查（`artifacts/verification-1.2.12-20261031/resource-default-recheck/resource-profile.json`） 和 直接合成（`artifacts/verification-1.2.12-20261031/resource-direct-composition/resource-profile.json`）。**正式 MainWindow 的无障碍与渲染行为均未禁用或变更；UIA 抑制条件下的低占用不能作为正式应用性能通过的结论，默认条件 CPU 目标仍未完全验收。**这些是不同进程的隔离对照，没有优化前生产版本同条件 A/B 或瓦数功耗测量。
